# Demo Runbook｜決賽現場執行手冊

**2026 中華電信智慧創新應用大賽 · 總決賽 · 每隊 12 分鐘**

這份不是技術文件。這是**站在台上、手在抖的時候照著念的稿子**。
每一段都寫清楚：按什麼、看哪裡、講什麼、出事了怎麼辦。

> 只要記得一件事：**Demo 掛了不會輸，慌了才會輸。**
> 每一種掛法下面都寫好了下一句話怎麼接。

---

## 0. 三十秒版本

```bash
factory-guardian stage                    # 正式演出：四分鐘，八段，自己走
factory-guardian stage --offline          # 網路掛了就加這個旗標，其他都一樣
factory-guardian stage --speed rehearsal  # 一分鐘彩排（同一齣戲，只是快轉）
factory-guardian stage-check --runs 30    # 評審問「穩不穩」時，當場跑給他看
```

按下去之後**不要碰鍵盤**。系統會自己走完八段，每段結束會把該段的結論與數字印出來。
你的工作只有一件：照著下面第 4 節的口白講。

## 2. 開演前檢查清單

### T–30 分鐘（在後台）

```bash
cd <專案目錄>
factory-guardian stage-check --runs 30          # 應該看到 30/30、決策一致
factory-guardian stage-check --runs 10 --offline # 最壞情況也要 10/10
```

- [ ] 連續成功次數 = 執行次數（30/30）
- [ ] 決策一致性顯示「一致」（只有一個指紋）
- [ ] 資料遺失率 0.00%
- [ ] 離線那輪有印出「離線備援時間」

任何一項不對 → **不要上台改程式**。改用 `--offline` 演出（見第 5 節），
或直接播預錄影片。現在不是 debug 的時候。

### T–5 分鐘（在台上，投影機已接好）

- [ ] 終端機字體放大到**後排看得見**（至少 18pt），視窗最大化
- [ ] 深色背景、關閉所有通知（Slack / 郵件 / 系統更新）
- [ ] 螢幕保護與睡眠關閉
- [ ] 先跑一次 `factory-guardian stage --speed fast --no-audit`（**兩秒內**就會跑完），
      確認最後一行是「DEMO 成功」，然後**清空畫面**（`clear`）
- [ ] 預錄影片檔案已開好，放在另一個桌面／分頁，隨時可切
- [ ] 手機熱點已開（但**不要依賴它**——我們的 Demo 本來就不需要網路）

### 正式那一刻

打好指令但**先不要按 Enter**，等主講講完架構那一頁再按。

```bash
factory-guardian stage
```

## 3. 演出時的三個原則

1. **不要碰鍵盤。** 系統自己會走。你一插手就可能中斷它。
2. **數字念畫面上的，不要背。** 每一段最後那張表就是給你念的。
   數字每次執行都一樣（固定 seed），但**照著念**永遠比背安全 ——
   下面稿子裡的數字是排練時的值，**一律以畫面為準**。
3. **每段結束的那句青色的話，就是那段的結論。** 念完它，再進下一段。

---

## 4. 八段劇本逐段稿

八段對應研究文件 §5.1 的表格。畫面上會自己印出時間窗與段落名稱。

### A1 · 0:00–0:25 · 正常狀態

**畫面**：三台機台的狀態、健康度、產線達成率、CAM-01 看到的當班人員。

**你講**：
> 「這是一條正在跑的產線。三台機台、健康度 100、產線達成率接近 100%，
> 攝影機看到一名人員在安全走道上。**這些不是截圖，是模擬器此刻的狀態。**」

**別講**：技術細節。這一段只是建立基準線，讓後面的變化有對比。

---

### A2 · 0:25–0:55 · 異常出現

**畫面**：感測讀值（振動變 warning）、觸發條件、偵測延遲。

**你講**：
> 「故障在第 2 分鐘注入，系統在第 5 分鐘叫出來——**偵測延遲 3 分鐘**。
> 注意觸發條件這一行：它不是單一門檻，是門檻、趨勢與健康度一起看的。」

**如果評審問「是不是你手動按的異常」**：
> 「注入時點寫在情境定義裡、固定不變，這樣才能重複驗證。
> 但**偵測是 Agent 自己做的**——它不知道我們注入了什麼。」

---

### A3 · 0:55–1:30 · 多模態診斷

**畫面**：研判根因、信心度、候選數、**證據模態種類**、排名權重。

**你講**：
> 「Agent 提出根因。請看『證據模態』這一格——這次診斷用到了感測器、聲音、
> 影像、手冊、SOP 與歷史工單。**排名是規則引擎用固定權重算的，不是 LLM 說了算。**
> LLM 在這裡只做一件事：把算好的結果寫成人看得懂的文字。」

---

### A4 · 1:30–2:05 · 證據與替代假設

**畫面**：可引用證據（手冊條號、歷史案例編號）、替代假設與各自分數、信心門檻、續觀察時間。

**你講**：
> 「每一條結論都指得回來源：手冊第幾條、哪一張歷史工單、資料是哪個時間點的。
> 落選的假設也攤開來，連分數一起給你看。
> 還有一個細節：信心度不到門檻時，系統**選擇繼續觀察**，而不是急著動設備。
> 那幾分鐘就印在『續觀察』那一格。」

這是最容易加分的一段。**慢一點講。**

---

### A5 · 2:05–2:35 · 處置建議

**畫面**：受影響訂單、候選方案、**被 Safety 阻擋的方案**、推薦方案與預測值。

**你講**：
> 「四個方案，每一個都在模擬器上乾跑過——這些產能與延遲數字是**跑出來的，不是估的**。
> 請看被擋下的這一個：規則 SR-02P 說，維持全速會讓振動從現在的值升到超過危險門檻。
> **Safety 是硬限制，不是加權項**——它不參與比分，它直接把方案刪掉。
> 剩下的才由規則引擎加權排名。」

---

### A6 · 2:35–3:05 · 核准與工單

**畫面**：待核准方案、風險等級、核准者、工單編號與完整度。

**你講**：
> 「停機與維修是高風險動作，系統**停在這裡等人**。風險等級由 Policy Engine 判定，
> 核准者與理由會寫進稽核軌跡——這是不可否認的紀錄。
> 核准之後，工單自動開出來：優先度、需要的技能、零件、SOP、預估工時，完整度 100%。」

**想更有戲劇性**：用 `factory-guardian stage --manual-approval`，
系統會真的停下來等你按 `y`。**但只有彩排過三次以上才這樣做。**

---

### A7 · 3:05–3:35 · 維修與驗證

**畫面**：執行結果逐條、驗證項目（預期 vs 實測）。

**你講**：
> 「執行**真的改變了工廠狀態**：轉單、停機、派工。
> 然後最重要的一步——驗證。每一項都是執行後**回到孿生體重新量**的實測值，
> 不是把剛才的預測抄一遍。三項全部通過。」

---

### A8 · 3:35–4:00 · 成果總結

**畫面**：反應時間、處置時間、產能達成率、**避免的停機損失**、稽核筆數、決策指紋。

**你講**：
> 「四分鐘結束。反應時間 3 分鐘、處置時間 5 分鐘、產能達成率 97%、設備健康度回到 100。
> 對照組是同一顆種子、同一段時間、只告警不處置——產能 39%，設備健康度剩 0.7，
> 而且發生了二次損壞。**中間這段差額就是這套系統的價值。**
> 最後這一行是決策指紋：這場 Demo 的所有決策壓成一個雜湊值。
> 我們連續跑 30 次，**指紋每一次都一樣**。」

## 5. 出事了怎麼辦

### 情況 A：現場網路斷了

**不用慌，這是我們的強項。** 按 Ctrl+C，改跑：

```bash
factory-guardian stage --offline
```

**你講**：
> 「網路剛好斷了，那正好——我直接演給各位看。
> 這個旗標模擬的是廠區對外鏈路中斷。閉環的每一站都在邊緣完成，
> 只有 LLM 敘述降級成邊緣確定性敘述器，而且每一次降級都寫進稽核軌跡。」

演完之後指著最後那行：
> 「**離線備援時間**印在這裡。而且——決策指紋和有網路時**完全一樣**。
> 斷網不是走了另一條比較差的路，是走了同一條路。」

### 情況 B：Demo 跑到一半卡住 / 報錯

1. 深呼吸，**不要開始 debug**。
2. Ctrl+C，說一句：「我切到預錄畫面，內容完全一樣。」
3. 播預錄影片，繼續照第 4 節的稿子講。
4. 講完之後（如果還有時間）再說：
   > 「順帶一提，我們有一個連續 30 次的穩定度測試。」
   > 然後跑 `factory-guardian stage-check --runs 30`。它比整場 Demo 還快（約 3 秒）。

### 情況 C：機器整台掛了 / 投影機不亮

- 切備用筆電（**兩台都要事先跑過檢查清單**）。
- 兩台都不行 → 直接播預錄影片，用手機／平板都行。
- 影片也放不了 → **口頭講完八段**，把提案書的 Demo 那幾頁翻給評審看。
  八段的順序你已經背了：正常 → 異常 → 診斷 → 證據 → 建議 → 核准 → 驗證 → 總結。

### 情況 D：時間不夠了（前面超時）

用快轉，不要跳段：

```bash
factory-guardian stage --speed rehearsal    # 一分鐘跑完同樣八段
```

八段全在，只是節奏快。**跳段會讓論證斷掉，快轉不會。**

### 情況 E：評審中途打斷提問

停下來回答。系統會停在當前段落等你——它不會自己往下衝。
回答完之後接一句：「我們回到 A5，剛才講到 Safety 把這個方案擋下來。」

## 6. 評審最可能問的五題

| 問題 | 回答 | 佐證怎麼調 |
|---|---|---|
| 「數字是不是編的？」 | 「Sensor / Orders / Manual 都標明是合成資料，但事件、Agent 決策、狀態更新與 KPI 驗證都是真的執行。每一場的稽核軌跡都可以調出來。」 | `factory-guardian audit runs/audit-*.jsonl` |
| 「你的 Demo 穩定嗎？」 | 「連續 30 次，成功率 100%，決策指紋每次相同。」 | `factory-guardian stage-check --runs 30`（約 3 秒） |
| 「斷網怎麼辦？」 | 「閉環完全在邊緣跑得完，決策一個字都不會變。」 | `factory-guardian stage --offline --speed fast` |
| 「憑什麼說你比較好？」 | 「三組對照組，同一顆種子、同一段時間。」 | `factory-guardian benchmark` |
| 「LLM 會不會亂下指令？」 | 「LLM 只寫敘述。排名是規則引擎，安全是硬規則，執行前還有 Policy 與 Safety 兩道閘門。」 | A5 那段的「排名由規則引擎計算」 |

## 7. 演完之後

```bash
ls -t runs/audit-*.jsonl | head -1        # 這場的稽核軌跡
factory-guardian audit runs/audit-*.jsonl # 需要時當場攤開給評審看
```

`factory-guardian stage --out stage.json` 會把整場（八段、所有數字、判準、指紋）
存成一份 JSON，可以直接附在提案書後面。

## 附錄：指令速查

| 指令 | 用途 |
|---|---|
| `factory-guardian stage` | 正式演出，四分鐘 |
| `factory-guardian stage --speed rehearsal` | 一分鐘彩排 |
| `factory-guardian stage --speed fast` | 30 秒內驗證能不能跑 |
| `factory-guardian stage --offline` | 最壞情況：無金鑰 ＋ 斷網 |
| `factory-guardian stage --manual-approval` | A6 真的停下來等你按 y |
| `factory-guardian stage --no-cue` | 不印口白提示（畫面更乾淨） |
| `factory-guardian stage --script` | 只印劇本，不執行（背稿用） |
| `factory-guardian stage --out stage.json` | 存成 JSON |
| `factory-guardian stage-check --runs 30` | 穩定度統計 |
| `factory-guardian stage-check --runs 30 --offline` | 最壞情況的穩定度統計 |

> 劇本的節奏可以改：段落時間定義在 `factory_guardian/stage/script.py` 的 `SCRIPT`。
> 改 `end_s` 就好，八段的內容與順序不要動——那是研究文件 §5.1 的表格。
