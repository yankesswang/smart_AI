# 一、執行摘要

**核心結論｜**社會組提案不應停留在「LLM 聊天」或「RAG 知識庫」，而應呈現可觀測、可推演、可執行、可驗證的 Agentic AI 閉環；同時必須與中華電信的網路、門號、雲端、衛星、資安及企業客戶資源產生不可替代的連結。

本次討論由廣泛發想逐步收斂，經歷「題目創意」、「中華電信價值」、「資料與 Demo 可行性」、「技術差距」及「企業級包裝」五個階段，最後形成六個候選旗艦提案。

# 二、比賽評分與選題原則

## 社會組決賽的真正重點

| **評選項目** | **比重** | **提案應回答的問題** |
| --- | --- | --- |
| 技術成熟度 | 40% | 是否真的運行？是否有完整度、擴充性與安全治理？ |
| 商業價值與市場性 | 40% | 誰會付錢？中華電信可增加營收或降低多少成本？ |
| 業務可落地性 | 10% | 能否直接與中華電信的網路、雲端、資安或客戶通路結合？ |
| 永續發展性 | 10% | 是否提升數位韌性、普惠、安全、醫療或減碳價值？ |

## 本次確立的四項硬標準

- 好 Demo：現場能看到事件發生、Agent 判斷、工具呼叫、系統執行及量化改善。
- 有技術差距：不能只有聊天介面；至少結合數位孿生、知識圖譜、最佳化、政策治理、Edge AI 或閉環驗證。
- 中華電信願意買單：能帶動門號、專線、5G、衛星、HiCloud、資安或企業代管收入，或明確降低內部成本。
- 高階包裝：題目必須是基礎設施、平台或企業級服務，而非單一小工具。

## 判斷一句話

**選題公式｜**中華電信獨有資產 × 可閉環執行的 Agent × 可量化 Demo × 可訂閱或代管的企業服務。

# 五、企業網路維運 AI Agent：原始案例

**NetOps Copilot**｜電信級企業網路自主維運與故障處理 Agent

## 原始價值主張

將企業網路的報障、資料蒐集、初步診斷、知識查詢、處置建議與工單建立自動化，降低客服與維運成本，並包裝為企業網路加值服務。

## 多 Agent 架構

| **Agent** | **職責** |
| --- | --- |
| 監控 Agent | 分析延遲、斷線、封包遺失、設備告警及使用者回報 |
| 診斷 Agent | 區分企業內網、Wi-Fi、CPE、線路或外部服務問題 |
| 知識 Agent | 以 RAG 查詢設備手冊、SOP、案例與 SLA |
| 處置 Agent | 提出安全修復方案；高風險操作要求人工確認 |
| 工單 Agent | 整理客戶、設備、時間、檢測及建議，形成結構化工單 |

## 為何中華電信可能買單

- 降低客服平均處理時間、轉接次數與不必要派修。
- 提高首次解決率及企業客戶 SLA 體驗。
- 可包裝為企業網路、SD-WAN、企業專線或多據點管理的訂閱服務。
- 中華電信可利用線路、CPE、歷史工單與企業客戶通路形成資料優勢。

## 關鍵可行性問題

**討論結論｜**若團隊沒有真實設備、SNMP／NetFlow、線路狀態、歷史工單或網路維運能力，Demo 很容易退化成假資料加聊天畫面，難以通過社會組「技術成熟度」的追問。

- 評審會追問資料來源與判斷正確性。
- Agent 是否真的執行診斷，或只是生成文字。
- 是否具備設備、權限、資安及回復機制。
- 模擬資料若缺乏真實流量與故障行為，可信度不足。

# 六、可行性修正版：SME Resilience Agent

**SME Resilience Agent**｜中小企業數位韌性健檢與中華電信方案配置 Agent

企業輸入網站並完成簡短問卷後，Agent 實際檢查 HTTPS、TLS、DNS、SPF／DKIM／DMARC、安全標頭、網站可用性與備援現況，產生韌性評分、改善路線及中華電信服務建議。

## 優點

- 公開資料與可控問卷即可完成，不需要電信內部資料。
- 評審可現場輸入網址，看見 Agent 真正執行檢測。
- 能將免費健檢轉換為企業專線、HiCloud、備份、DDoS、資安與代管服務商機。
- 可量化韌性分數、風險數量、改善優先序及潛在商機。

## 限制

雖然 Demo 可行、商業模式清楚，但技術與舞台高度仍可能不足，因此後續再往「數位孿生、通訊調度與自主閉環」升級，形成 AegisMesh。

# 七、旗艦方案演進：AegisMesh 天穹韌網

**海地星空多網融合的 Agentic AI 通訊韌性數位孿生平台**

**一句話定位｜**當光纖中斷、基地台壅塞或災害發生時，AI Agent 在數位孿生中推演替代方案，再協調固網、5G、衛星與邊緣資源，確保關鍵服務不中斷。

## 建議 Demo 場景：智慧醫院園區

- 關鍵服務：急診、遠距診療、醫療影像、生理監測 IoT。
- 一般服務：行政系統及訪客 Wi-Fi。
- 通訊路徑：主要光纖、5G 備援與衛星緊急通訊。
- 災害情境：颱風造成光纖中斷，同時 5G 基地台壅塞。

## Agent 閉環

- Telemetry Agent 偵測光纖中斷、延遲與 5G 壅塞。
- Impact Agent 判斷受影響服務與 SLA。
- Planning Agent 產生多個復原方案。
- Simulation Agent 在數位孿生推演成效。
- Policy Agent 檢查資安、成本、權限與風險。
- Orchestrator Agent 提交方案，經人工核准後執行。
- Verification Agent 驗證服務恢復，失敗則重新規劃。

## Demo 技術實作

| **技術** | **用途** |
| --- | --- |
| Containerlab／Mininet | 建立可實際傳送流量的虛擬網路 |
| Linux tc/netem | 注入延遲、壅塞、斷線與封包遺失 |
| Prometheus／Grafana | 收集並呈現即時網路指標 |
| NetworkX／Neo4j | 建立網路與業務服務依賴圖 |
| LLM 多 Agent | 理解事件、規劃、協調與解釋 |
| 最佳化演算法 | 計算路徑、頻寬及服務優先級 |
| Policy-as-Code | 限制 Agent 操作並保留人工核准 |

**可信度重點｜**拓樸可以是競賽環境，但流量、延遲、故障注入、工具呼叫、路徑切換與恢復指標都必須是真的。

## 商轉定位

- CHT Resilience-as-a-Service：企業通訊韌性代管。
- 目標客戶包括醫院、金融、政府、園區、港口、機場與大型企業。
- 收入來源包含初期建置、平台訂閱、據點計費、衛星／5G 備援、SLA 代管與災害演練。

# 提案 1｜AegisMesh 天穹韌網

**海地星空多網融合的 Agentic AI 通訊韌性數位孿生平台**

| **欄位** | **內容** |
| --- | --- |
| 競賽主題 | 智慧通信／智慧醫療／海地星空應用／數位韌性 |
| 產品定位 | 為醫院、政府與關鍵企業提供跨固網、5G、衛星及 Edge 的自主韌性調度服務。 |
| Demo 原則 | 必須呈現真實事件、Agent 決策、工具執行與前後量化結果 |

## 舞台 Demo

- 顯示智慧醫院的光纖、5G、衛星拓樸及關鍵服務。
- 注入光纖中斷與 5G 壅塞，呈現服務可用率下降。
- 多 Agent 分析影響、生成方案並在數位孿生推演。
- 人工核准後實際切換虛擬路徑與流量優先級。
- 展示可用率、恢復時間、延遲與人工步驟的前後比較。

## 技術差距

- 網路與業務服務知識圖譜。
- LLM 與最佳化演算法混合決策。
- 數位孿生先推演、後執行。
- Policy Agent、人工核准與完整稽核。
- Observe－Plan－Simulate－Approve－Execute－Verify 閉環。

## 中華電信買單理由

- 直接連結中華電信固網、5G、衛星、HiCloud、Edge 及 NOC／SOC。
- 可提高企業客戶合約價值與服務黏著度。
- 可形成高毛利的韌性代管、SLA 與災害演練服務。

## MVP 資料與實作方式

- 以 8－12 個虛擬節點建立智慧醫院拓樸。
- 以 Containerlab／Mininet 及 tc/netem 產生真實流量與故障。
- 只做 3 種災害情境、5 種關鍵應用及 4－5 個 Agent。

## 商業模式

- 平台訂閱與據點計費。
- 5G／衛星備援、企業專線與 HiCloud 綁售。
- 7×24 代管、SLA 與災害演練顧問費。

**主要風險｜**系統整合難度最高；必須嚴格控制 MVP 範圍，不應宣稱直接控制全國電信網路。

# 提案 2｜TrustCall Sentinel 全民通訊信任盾

**結合通話語意、深偽聲音、簡訊與網站情資的即時多模態防詐 Agent**

| **欄位** | **內容** |
| --- | --- |
| 競賽主題 | 智慧生活／智慧金融／智慧通信 |
| 產品定位 | 從門號黑名單升級為跨通話、簡訊、網址與帳戶的即時詐騙意圖防護。 |
| Demo 原則 | 必須呈現真實事件、Agent 決策、工具執行與前後量化結果 |

## 舞台 Demo

- 進行一通模擬「假冒親友匯款」詐騙電話。
- 系統即時顯示語音逐字稿、詐騙話術、急迫性及深偽風險。
- Agent 關聯電話、網址與帳戶資訊並產生風險解釋。
- 高風險時啟動身分驗證、守護人通知與通報摘要。

## 技術差距

- 串流 ASR 與詐騙意圖辨識。
- 話術知識圖譜及跨通道事件關聯。
- 深偽聲音風險模型與不確定性校準。
- Edge LLM、隱私保護及人工確認。

## 中華電信買單理由

- 可直接成為行動門號、長者與家庭守護加值服務。
- 可與金融、保險及政府防詐合作。
- 提升門號信任、降低詐騙客訴與品牌風險。

## MVP 資料與實作方式

- 使用公開詐騙案例、165 宣導內容、自建劇本與合成語音。
- 以 SIP／網頁語音建立可重複的現場通話流程。
- 至少準備真陽性、假陽性及非詐騙三種對照情境。

## 商業模式

- 每門號每月訂閱。
- 家庭守護群組方案。
- 企業員工防詐及金融 API 服務。

**主要風險｜**若只做文字分類會高度同質化；必須展現串流、多模態、跨通道關聯及安全介入。

# 提案 3｜Agent Passport 智慧代理人信任護照

**以門號、eSIM 與可驗證憑證建立 AI Agent 身分、授權及交易信任層**

| **欄位** | **內容** |
| --- | --- |
| 競賽主題 | 智慧通信／智慧金融／智慧生活 |
| 產品定位 | 讓服務商知道 Agent 屬於誰、獲得什麼授權、可以花多少錢及如何追溯。 |
| Demo 原則 | 必須呈現真實事件、Agent 決策、工具執行與前後量化結果 |

## 舞台 Demo

- 使用者授權旅遊 Agent 安排一萬元內的高雄行程。
- Agent 查詢交通與住宿，交易前驗證身分、權限與預算。
- 低風險訂位依授權完成；超額交易由 Policy Agent 阻擋。
- 使用者以門號／裝置確認後才能放行，系統保留完整授權紀錄。
- 再展示惡意 Agent 嘗試購買高價商品而被拒絕。

## 技術差距

- Agent 身分憑證與裝置／門號綁定。
- OAuth 2.1、細粒度授權及 Verifiable Credentials。
- 預算、時間、資料範圍與可撤銷 Policy Engine。
- Agent 行為簽章及不可否認稽核。

## 中華電信買單理由

- 把中華電信由連線提供者升級為 Agent 經濟的信任營運商。
- 可服務電商、金融、旅遊、支付與企業 Agent 平台。
- 門號、eSIM、帳單與裝置驗證是電信業的天然優勢。

## MVP 資料與實作方式

- 使用自建服務商 API、模擬門號身分及憑證簽發。
- 限定「授權與交易信任」MVP，不需建立完整生態系。
- 準備正常、超額、逾期及撤銷授權四種情境。

## 商業模式

- 每次 Agent 驗證／簽章收費。
- 企業 API、風險評分及治理平台訂閱。
- 與電信帳單、小額支付及金融合作分潤。

**主要風險｜**概念前瞻但較抽象；Demo 必須用「正常交易與惡意越權對比」讓價值一眼看懂。

# 提案 4｜Formosa Sovereign Agent Fabric

**運行於 HiCloud 與企業私有環境的主權級多代理人平台**

| **欄位** | **內容** |
| --- | --- |
| 競賽主題 | 智慧通信／智慧金融／智慧醫療 |
| 產品定位 | 讓政府、金融與醫療在資料不外流的前提下部署可治理、可稽核的企業 Agent。 |
| Demo 原則 | 必須呈現真實事件、Agent 決策、工具執行與前後量化結果 |

## 舞台 Demo

- 以醫院採購流程展示採購、合約、預算及個資 Agent 協作。
- 當 Agent 嘗試將敏感資料送往外部模型，Policy Engine 即時阻擋。
- 系統改由 HiCloud／本地模型執行，並保留決策軌跡。
- 拔除外部模型連線，展示服務仍能降級運作。

## 技術差距

- 多模型路由與本地／雲端混合推論。
- Agent 權限隔離、資料分類與遮罩。
- Prompt Injection 防護及 Policy-as-Code。
- 行為回放、可觀測性與外部服務降級策略。

## 中華電信買單理由

- 直接帶動 HiCloud、GPU、企業專線、零信任、SOC／MDR。
- 符合政府、金融、醫療對資料主權與稽核的需求。
- 適合大型企業及政府標案。

## MVP 資料與實作方式

- 使用自建敏感資料集與本地小模型。
- 以外送資料、越權存取及 Prompt Injection 作攻防情境。
- 輸出每一步的模型、資料、權限及決策紀錄。

## 商業模式

- 平台與治理模組訂閱。
- GPU／推論使用量計費。
- 私有部署、整合與維運服務費。

**主要風險｜**企業價值明確但容易像平台簡報；必須把資料外洩阻擋與斷線降級做成可視化攻防 Demo。

# 提案 5｜SkyCare Continuum 無界醫療韌性網

**融合 5G、衛星、Edge AI 與臨床 Agent 的連續醫療服務平台**

| **欄位** | **內容** |
| --- | --- |
| 競賽主題 | 智慧醫療／智慧通信／海地星空應用 |
| 產品定位 | 在偏鄉、離島、救護車與災區網路不穩時，維持關鍵醫療資料及遠距協作不中斷。 |
| Demo 原則 | 必須呈現真實事件、Agent 決策、工具執行與前後量化結果 |

## 舞台 Demo

- 救護車傳送生命徵象、影像與救護人員語音。
- Clinical Agent 產生結構化事件摘要。
- 注入 5G 訊號下降，Network Agent 重新評估頻寬。
- 影片降級為關鍵影格，必要資料改走衛星，部分推論留在 Edge。
- 網路恢復後自動同步完整資料並生成交班摘要。

## 技術差距

- 多模態醫療事件整合。
- 網路感知型 Agent 與 Edge／Cloud 任務分配。
- 按臨床重要性進行傳輸降級及斷線續傳。
- 醫療資料權限、隱私與可追溯性。

## 中華電信買單理由

- 帶動 5G、衛星、專網、HiCloud、Edge 與資安服務。
- 可銷售給醫療體系、地方政府、消防救護與長照機構。
- 具偏鄉醫療、災防及社會影響力。

## MVP 資料與實作方式

- 使用模擬生命徵象、公開醫療樣例與自建視訊。
- 以網路限速及斷線工具真實改變傳輸條件。
- 系統只做通訊調度與決策支援，不宣稱取代醫師診斷。

## 商業模式

- 醫療院所平台授權及據點計費。
- 5G／衛星韌性通訊與 Edge 設備租用。
- 政府偏鄉醫療與災防專案。

**主要風險｜**需避免醫療責任與過度宣稱；核心應定位於資料連續性及通訊韌性。

# 提案 6｜CarbonGrid Autopilot 通訊能源自治中樞

**在維持電信 SLA 下，由多 Agent 協調基地台、機房、電池與再生能源**

| **欄位** | **內容** |
| --- | --- |
| 競賽主題 | 智慧環境／智慧通信 |
| 產品定位 | 同時降低電力成本、碳排及尖峰負載，並維持電信與企業服務品質。 |
| Demo 原則 | 必須呈現真實事件、Agent 決策、工具執行與前後量化結果 |

## 舞台 Demo

- 顯示三個基地台與一個 Edge 機房的流量、電價、碳排及電池狀態。
- 注入晚間流量尖峰與電價上升。
- Agent 預測負載並生成多目標調度方案。
- 移轉部分運算、調整非關鍵設備、使用儲能削峰並保留災害備援。
- 展示成本、碳排、電池健康及 SLA 前後結果。

## 技術差距

- 時間序列預測與多目標最佳化。
- 能源數位孿生及多 Agent 協商。
- SLA、電池健康、成本與碳排多重約束。
- 執行後回饋學習與策略驗證。

## 中華電信買單理由

- 可降低中華電信基地台及機房能源成本。
- 可對外銷售企業能源管理與低碳 ICT 服務。
- 符合永續與淨零方向，成果容易量化。

## MVP 資料與實作方式

- 使用公開電價、天氣及碳排資料。
- 自建站點流量、電池與再生能源數位孿生。
- 以固定基準策略對照 Agent 調度成效。

## 商業模式

- 節能 SaaS 平台訂閱。
- 依節省電費或減碳成效分潤。
- 企業機房及園區能源代管。

**主要風險｜**若沒有能源／最佳化能力，容易只剩儀表板；必須證明調度演算法在 SLA 約束下優於基準策略。

## 依策略選擇

- 最高綜合勝率：AegisMesh 天穹韌網。
- 最低實作風險：TrustCall Sentinel 全民通訊信任盾。
- 最高前瞻性：Agent Passport 智慧代理人信任護照。
- 最清楚的企業營收：Formosa Sovereign Agent Fabric。
- 最強社會影響與視覺效果：SkyCare Continuum。
- 若團隊有能源或最佳化背景：CarbonGrid Autopilot。

## 建議決策順序

- 先確認團隊的核心技術能力：網路、資安、語音、身分、雲端、醫療或最佳化。
- 用兩週內能完成的「真實閉環 Demo」反推選題，而不是先選最宏大的題目。
- 為前三名各製作一頁 Demo Storyboard，評估資料、工具與失敗風險。
- 選定一案後，將 MVP 限制在單一場域、三個情境及一條完整 Agent 閉環。
- 再撰寫正式提案、系統架構、商業模式、驗證指標及中華電信合作需求。

# 九、所有提案共同的技術底線

| **一般作品** | **建議競賽作品** |
| --- | --- |
| 使用者提問，RAG 查詢，LLM 回答 | 事件感知、任務規劃、工具執行、狀態驗證及失敗重試 |
| 只展示聊天紀錄 | 展示即時指標、Agent 軌跡、決策依據及量化成效 |
| LLM 直接決定所有答案 | LLM 負責理解；演算法、規則及政策負責可驗證決策 |
| 以假資料播放結果 | 使用公開資料、實驗環境或可重複的真實工具產生資料 |
| 沒有安全邊界 | 最小權限、人工核准、Policy-as-Code 及完整稽核 |
| 只有技術亮點 | 同時提出客戶、定價、導入方式及中華電信收入連結 |

**最後原則｜**範圍可以小，但閉環必須完整；故事可以高階，但 Demo 必須可信；Agent 可以自主，但高風險操作必須受到政策與人工治理。
